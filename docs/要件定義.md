# YouTube ダウンローダー 要件定義書

## 0. 前提と重要な技術的制約

本書は「GitHub Pages でホストする YouTube ダウンロードサイト」の要件を定義する。
設計上の出発点として、以下の制約を先に確定させる。

### 0.1 GitHub Pages は静的ホスティングである

GitHub Pages はサーバーサイド処理を実行できない。したがって Next.js は
**Static Export（`output: 'export'`）** でビルドし、Server Actions・API Routes・
Server Component でのデータ取得は使用できない。

本リポジトリの標準構成（loaders + Server Actions）はそのままでは適用できないため、
**Phase 1 ではデータ取得を全てクライアントサイドで行う**。
DDD 4層の依存方向とファイル配置ルールは維持する（domain / application は
実行環境に依存しないため、そのまま再利用できる）。

### 0.2 ブラウザ単体では実際の動画取得は完結できない

ユーザー要望は「ブラウザ内完結」だが、以下の理由により
ブラウザ JavaScript のみで YouTube から動画データを取得することは不可能である。

| 障壁 | 内容 |
|---|---|
| CORS | 動画配信元 `*.googlevideo.com` は `Access-Control-Allow-Origin` を返さない。`fetch` は必ず失敗する |
| 署名解決 | 動画 URL は player JS 内の難読化関数で署名を計算しないと有効化されない。仕様変更が頻繁で保守困難 |
| ストリーム分離 | 720p を超える画質は映像と音声が別ストリーム。結合に ffmpeg 相当の処理が必要 |
| CPU / メモリ | ffmpeg.wasm での結合は数百 MB のメモリを消費し、モバイルブラウザで実用に耐えない |

### 0.3 本書が採用する解決方針（フェーズ分割）

上記を踏まえ、要望「ブラウザ内完結」と「サーバー側変換・1080p対応」を
時間軸で分離して両立させる。

| | Phase 1（本リリース範囲） | Phase 2（拡張） |
|---|---|---|
| ホスティング | GitHub Pages 単体 | GitHub Pages + 外部 API |
| 動画情報取得 | Stub Gateway（モックデータ） | 実 API |
| ダウンロード | Stub（ダミーファイル生成） | ストリーミングプロキシ |
| 変換 | なし | サーバー側 ffmpeg |
| 最大画質 | UI 上は 1080p まで選択可能 | 1080p まで実取得 |

Phase 1 の目的は **UI・UX・ドメインロジックを完成させること**であり、
Gateway interface を Phase 2 でそのまま差し替えられる形に設計する。
`CLAUDE.md` の「外部 API の Gateway は必ず Stub 実装を用意し、
Composition で環境変数に応じて切り替える」ルールに完全に従う。

### 0.4 保存先について

Phase 2 で API を導入しても、**サーバーは動画ファイルを一切保管しない**。
取得したストリームをそのままブラウザへ中継し、ブラウザの
ダウンロード機構（`Content-Disposition: attachment`）で
ユーザーの端末に保存される。ユーザー体験としては「自分の端末に保存される」
という要望を完全に満たす。

## 1. 概要

YouTube の動画 URL を入力すると、動画情報をプレビューし、
MP4（動画）・MP3（音声のみ）・字幕ファイルとしてユーザーの端末に
保存できる Web サイトを GitHub Pages 上に構築する。
再生リスト URL にも対応し、一括処理を可能にする。

### 1.1 ターゲットユーザー

- 自分がアップロードした動画のバックアップを取りたい配信者
- Creative Commons ライセンス動画をオフラインで参照したい利用者
- オフライン環境で学習コンテンツを視聴したい利用者

### 1.2 スコープ外

- 動画の編集・トリミング機能
- サーバー上での動画の永続保管
- ユーザー登録・認証（Phase 1/2 とも不要）
- 有料コンテンツ・限定公開動画・DRM 保護コンテンツへの対応

## 2. 法的事項・免責

### 2.1 方針

機能面での URL 制限は設けない。**サイト上での明示的な注意喚起**によって
利用者の責任を明確化する方針を採る。

### 2.2 表示要件

- **トップページ常設バナー**: 「本サービスは YouTube の利用規約により、
  権利者の許諾がある動画（自身がアップロードした動画、Creative Commons
  ライセンス動画等）のみを対象としています」を画面上部に常時表示する
- **初回利用時の同意ダイアログ**: 初回アクセス時に免責事項へ同意する
  ダイアログを表示し、同意状態を `localStorage` に保存する
- **利用規約ページ / 免責事項ページ**: `/terms`, `/disclaimer` として
  静的ページを用意し、フッターから常時到達可能にする
- **ダウンロード実行直前の確認**: ダウンロードボタン押下時に
  「この動画をダウンロードする権利を有していることを確認しました」という
  チェックを要求する

### 2.3 免責文言に含める内容

- 著作権侵害となる利用を禁止する旨
- 利用によって生じた損害について運営者は責任を負わない旨
- 各国の著作権法・YouTube 利用規約の遵守は利用者の責任である旨

## 3. 機能要件

### 3.1 動画情報プレビュー（必須）

| 項目 | 内容 |
|---|---|
| 入力 | YouTube 動画 URL または再生リスト URL |
| 対応 URL 形式 | `youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`, `youtube.com/playlist?list=`, `m.youtube.com/*` |
| 表示項目 | サムネイル、タイトル、チャンネル名、再生時間、投稿日、再生回数、説明文（折りたたみ） |
| バリデーション | URL 形式不正・動画 ID 抽出不可の場合はエラー表示 |
| 挙動 | URL 入力欄への貼り付け時に自動でプレビュー取得を開始（デバウンス 500ms） |

### 3.2 動画ダウンロード（MP4）（必須）

| 項目 | 内容 |
|---|---|
| 画質選択 | 1080p / 720p / 480p / 360p から選択。利用可能な画質のみ活性化 |
| デフォルト | 利用可能な最高画質（最大 1080p） |
| ファイル形式 | MP4（H.264 + AAC） |
| ファイル名 | `{動画タイトル}_{画質}.mp4`（OS で使用不可の文字はアンダースコアへ置換） |
| 進捗表示 | ダウンロード進捗をプログレスバーで表示（取得済みバイト数 / 総バイト数） |
| キャンセル | 実行中のダウンロードを中断できる |

### 3.3 音声のみ抽出（MP3）（必須）

| 項目 | 内容 |
|---|---|
| ビットレート選択 | 320kbps / 192kbps / 128kbps |
| デフォルト | 192kbps |
| ファイル形式 | MP3 |
| ファイル名 | `{動画タイトル}.mp3` |
| メタデータ | ID3 タグにタイトル・アーティスト（チャンネル名）・サムネイルを埋め込む |

### 3.4 字幕対応（必須）

| 項目 | 内容 |
|---|---|
| 言語選択 | 動画に存在する字幕言語の一覧から選択 |
| 自動生成字幕 | 対応する。一覧上で「自動生成」と明示する |
| 形式 | SRT / VTT から選択。デフォルトは SRT |
| ファイル名 | `{動画タイトル}.{言語コード}.srt` |
| 同時取得 | 動画ダウンロード時に字幕を同梱するオプションを提供 |

### 3.5 再生リスト対応（必須）

| 項目 | 内容 |
|---|---|
| 一覧表示 | 再生リスト内の全動画をサムネイル付きリストで表示 |
| 個別選択 | チェックボックスで対象動画を選択（全選択 / 全解除ボタンを提供） |
| 一括設定 | 画質・形式を一括で適用 |
| 逐次処理 | 同時実行数は 1 とし、キューで順次処理する（負荷とレート制限を考慮） |
| 進捗 | 「3 / 12 件完了」形式の全体進捗と、処理中動画の個別進捗を表示 |
| 上限 | 1 回あたり 50 件まで。超過分は警告を表示して切り捨てる |

### 3.6 ダウンロード履歴（任意）

- 直近 20 件の処理履歴を `localStorage` に保存し、トップページに表示
- 履歴からワンクリックで再ダウンロードできる
- 履歴の個別削除・全削除に対応
- 保存するのはメタデータのみ。動画ファイル自体は保存しない

## 4. 非機能要件

### 4.1 パフォーマンス

| 指標 | 目標値 |
|---|---|
| 初回表示（LCP） | 2.0 秒以内（GitHub Pages / 一般的な回線） |
| 動画情報取得の応答 | 3.0 秒以内 |
| バンドルサイズ | 初期 JS 200KB 以内（gzip 後） |
| Lighthouse Performance | 90 以上 |

### 4.2 対応環境

- **ブラウザ**: Chrome / Edge / Firefox / Safari の各最新 2 バージョン
- **デバイス**: スマートフォンファーストで設計。320px 幅から破綻しないこと
- **ダークモード**: OS 設定に追従（`prefers-color-scheme`）

### 4.3 アクセシビリティ

- キーボードのみで全ての操作が完結すること
- フォーム要素に適切な `label` を関連付けること
- 進捗・エラーを `aria-live` でスクリーンリーダーに通知すること
- コントラスト比 WCAG AA（4.5:1）を満たすこと

### 4.4 エラーハンドリング

以下のエラーを区別し、それぞれ利用者が次に取るべき行動を含むメッセージを表示する。

| エラー種別 | メッセージ方針 |
|---|---|
| URL 形式不正 | 対応している URL 形式の例を提示する |
| 動画が存在しない / 削除済み | URL の再確認を促す |
| 限定公開・年齢制限・地域制限 | 取得できない理由を明示する |
| ネットワークエラー | 再試行ボタンを提供する |
| 指定画質が利用不可 | 利用可能な画質を提示し、代替を選択させる |
| タイムアウト | 再試行を促す。3 回連続失敗時は時間をおくよう案内する |

### 4.5 セキュリティ

- 入力 URL は `URL` API でパースし、ホスト名のホワイトリスト検証を行う
- 取得したタイトル・説明文は React の自動エスケープに委ね、`dangerouslySetInnerHTML` を使用しない
- ファイル名生成時にパストラバーサル文字（`/`, `\`, `..`）を除去する
- Phase 2 の API では SSRF を防ぐため、リクエスト先を YouTube ドメインに限定する

### 4.6 プライバシー

- サーバーへの動画ファイル保存を行わない
- 個人を特定する情報を収集しない
- アクセス解析を導入する場合は Cookie を使用しない方式とする

## 5. 技術仕様

### 5.1 技術スタック

| 領域 | 採用技術 |
|---|---|
| フレームワーク | Next.js 15（App Router / Static Export） |
| 言語 | TypeScript |
| UI | React 19 + shadcn/ui + Tailwind CSS v4 |
| アイコン | lucide-react |
| 状態管理 | React の標準機能（`useState` / `useReducer`）。外部ライブラリは導入しない |
| テスト | Vitest（Unit） |
| Lint / Format | Biome |
| 依存検証 | dependency-cruiser |
| ホスティング | GitHub Pages（GitHub Actions によるデプロイ） |
| API（Phase 2） | Cloudflare Workers または Railway 上のストリーミングプロキシ |

### 5.2 Next.js Static Export 設定

```ts
// next.config.ts
const nextConfig = {
  output: 'export',
  images: { unoptimized: true },
  basePath: process.env.NODE_ENV === 'production' ? '/youtube-downloader' : '',
  trailingSlash: true,
}
```

- `basePath` はリポジトリ名に合わせる（`https://<user>.github.io/youtube-downloader/`）
- `next/image` の最適化はサーバーを要するため無効化する
- 動的ルート（`[id]`）は使用せず、クエリパラメータで状態を表現する

### 5.3 DDD 4層構成でのファイル配置

`CLAUDE.md` のレイヤールールに従い、以下の通り配置する。
Static Export により presentation 層は loaders / actions ではなく
Client Component から composition を直接呼ぶ形になる。

```
src/backend/
├── domain/
│   ├── models/
│   │   ├── video-url.model.ts          # URL パースと動画 ID 抽出
│   │   ├── video-info.model.ts         # 動画メタデータ
│   │   ├── download-format.model.ts    # 画質・ビットレート・形式
│   │   ├── subtitle-track.model.ts     # 字幕トラック
│   │   ├── playlist.model.ts           # 再生リスト
│   │   └── download-job.model.ts       # ダウンロードジョブと進捗
│   ├── services/
│   │   └── filename.service.ts         # 安全なファイル名生成
│   └── gateways/
│       └── youtube.gateway.ts          # 動画情報取得・ストリーム取得の interface
├── application/
│   └── usecases/
│       ├── fetch-video-info.usecase.ts
│       ├── fetch-playlist.usecase.ts
│       ├── download-video.usecase.ts
│       ├── download-audio.usecase.ts
│       └── download-subtitle.usecase.ts
├── infrastructure/
│   └── adapters/
│       ├── youtube-api.adapter.ts      # Phase 2: 実 API 呼び出し
│       └── youtube-stub.adapter.ts     # Phase 1: モックデータ
└── presentation/
    └── composition/
        └── youtube.composition.ts      # 環境変数による Stub / 本番切り替え
```

### 5.4 ドメインモデル設計方針

Rich Domain Model を必須とし、バリデーションと生成はモデル自身のメソッドで行う。
Domain 層のエラーは `Result<T, E>` 型で返し、throw しない。

```ts
// video-url.model.ts の想定インターフェース
export class VideoUrl {
  private constructor(
    readonly videoId: string,
    readonly playlistId: string | null,
  ) {}

  static from(raw: string): Result<VideoUrl, VideoUrlError> {
    // ホスト名検証 → 動画 ID / 再生リスト ID 抽出 → 失敗時は Err を返す
  }

  get isPlaylist(): boolean { /* ... */ }
}
```

### 5.5 Gateway interface

Phase 1 の Stub と Phase 2 の実装が同一 interface を満たすよう定義する。
ストリーム取得は進捗通知のため `ReadableStream` と総バイト数を返す。

```ts
// youtube.gateway.ts
export interface YoutubeGateway {
  fetchVideoInfo(videoId: string): Promise<VideoInfo>
  fetchPlaylist(playlistId: string): Promise<Playlist>
  openVideoStream(
    videoId: string,
    format: DownloadFormat,
    signal: AbortSignal,
  ): Promise<{ stream: ReadableStream<Uint8Array>; totalBytes: number | null }>
  openAudioStream(
    videoId: string,
    bitrate: AudioBitrate,
    signal: AbortSignal,
  ): Promise<{ stream: ReadableStream<Uint8Array>; totalBytes: number | null }>
  fetchSubtitle(
    videoId: string,
    languageCode: string,
    format: SubtitleFormat,
  ): Promise<string>
}
```

### 5.6 Composition による切り替え

```ts
// youtube.composition.ts
const useStub = process.env.NEXT_PUBLIC_USE_STUB === 'true'
const gateway: YoutubeGateway = useStub
  ? new YoutubeStubAdapter()
  : new YoutubeApiAdapter(process.env.NEXT_PUBLIC_API_BASE_URL!)
```

Phase 1 では `NEXT_PUBLIC_USE_STUB=true` を GitHub Actions のビルド環境変数に設定する。
Phase 2 で API を用意した際は、この環境変数を切り替えるだけで実装が入れ替わる。

### 5.7 Phase 2 API 仕様（将来実装）

Phase 2 で追加する外部 API の想定インターフェースを先に定義しておく。

| エンドポイント | メソッド | 説明 |
|---|---|---|
| `/api/info?v={videoId}` | GET | 動画メタデータと利用可能フォーマット一覧を JSON で返す |
| `/api/playlist?list={playlistId}` | GET | 再生リスト内の動画一覧を返す |
| `/api/download?v={videoId}&quality={quality}` | GET | MP4 をストリーミング返却（`Content-Disposition: attachment`） |
| `/api/audio?v={videoId}&bitrate={bitrate}` | GET | MP3 をストリーミング返却 |
| `/api/subtitle?v={videoId}&lang={lang}&format={format}` | GET | 字幕ファイルを返却 |

- CORS: GitHub Pages のオリジンのみ許可する
- レート制限: IP 単位で 10 リクエスト / 分
- サーバー上にファイルを保存せず、取得したストリームを都度中継する

## 6. 画面仕様

### 6.1 画面一覧

| パス | 画面名 | 内容 |
|---|---|---|
| `/` | トップ | URL 入力・プレビュー・ダウンロード操作・履歴 |
| `/terms` | 利用規約 | 静的テキスト |
| `/disclaimer` | 免責事項 | 静的テキスト |

### 6.2 トップページ構成

上から順に以下を配置する。

1. **注意喚起バナー** — 権利者の許諾がある動画のみが対象である旨（常時表示）
2. **ヘッダー** — サービス名とロゴ
3. **URL 入力エリア** — 入力フィールド + ペーストボタン + 解析ボタン
4. **プレビューカード** — URL 解析成功時に表示
   - 左（デスクトップ）/ 上（モバイル）: サムネイル
   - 右 / 下: タイトル、チャンネル名、再生時間、投稿日、再生回数
5. **形式選択タブ** — 「動画（MP4）」「音声（MP3）」「字幕」の 3 タブ
   - 動画タブ: 画質ラジオボタン + 字幕同梱チェックボックス
   - 音声タブ: ビットレートラジオボタン
   - 字幕タブ: 言語セレクト + 形式ラジオボタン
6. **権利確認チェックボックス** — 未チェック時はダウンロードボタンを非活性
7. **ダウンロードボタン** — 実行中はプログレスバーとキャンセルボタンに切り替わる
8. **履歴セクション** — 直近 20 件（履歴がある場合のみ表示）
9. **フッター** — 利用規約 / 免責事項 / リポジトリへのリンク

### 6.3 再生リスト時の表示

URL が再生リストと判定された場合、プレビューカードを
**動画一覧テーブル**に差し替える。

- ヘッダー行: 全選択チェックボックス、「N 件選択中」表示
- 各行: チェックボックス、サムネイル（小）、タイトル、再生時間、個別進捗
- 一括設定エリア: 画質・形式を全選択動画へ適用
- 実行中は処理中の行をハイライトし、完了行にチェックアイコンを表示

### 6.4 状態遷移

```
初期 ─URL入力→ 解析中 ─成功→ プレビュー表示 ─実行→ ダウンロード中 ─完了→ 完了表示
                  │                                    │
                  └─失敗→ エラー表示 ─再試行→ 解析中     └─キャンセル→ プレビュー表示
```

各状態で表示する要素を明確に分け、ローディング中はスケルトンを表示する。

## 7. テスト方針

`docs/テストガイドライン.md` および `docs/品質チェック・テスト規約.md` に従う。

### 7.1 Unit テスト（`test/unit/`）

domain と application を対象とし、Gateway はモックに差し替える。

| 対象 | 主なテスト観点 |
|---|---|
| `video-url.model` | 各 URL 形式からの ID 抽出、不正 URL の拒否、YouTube 以外のホストの拒否 |
| `filename.service` | 使用不可文字の置換、パストラバーサル文字の除去、長さ上限の切り詰め |
| `download-format.model` | 利用可能フォーマットの判定、デフォルト画質の選択ロジック |
| `playlist.model` | 50 件上限の切り捨て、選択状態の管理 |
| 各 UseCase | Gateway モックを用いた正常系・異常系の分岐 |

### 7.2 Integration テスト（`test/integration/`）

Phase 2 で API アダプタを実装した際に追加する。
`INTEGRATION_TEST=true` が未設定の場合はスキップする。

### 7.3 品質チェック

コード変更後は必ず `pnpm verify`（lint → prisma generate → typecheck →
unit test → depcruise）を実行し、全て通過することを確認する。

## 8. デプロイ

### 8.1 GitHub Actions ワークフロー

`.github/workflows/deploy-pages.yml` を追加する。

1. `develop` ブランチへの push をトリガーとする
2. pnpm で依存をインストール
3. `NEXT_PUBLIC_USE_STUB=true` を設定して `pnpm build`
4. 生成された `apps/webapp/out/` を GitHub Pages にデプロイ

### 8.2 リポジトリ設定

- Settings → Pages → Source を「GitHub Actions」に設定する
- 公開 URL: `https://<user>.github.io/youtube-downloader/`
- `.nojekyll` を出力ディレクトリに配置し、`_next/` が無視されないようにする
